# 语流(VoiceFlow Builder) — 产品需求文档 (PRD)

> 版本：v1.0 | 日期：2026-05-03

---

## 1. 产品概述

### 1.1 产品定位

语流(VoiceFlow Builder)是一款面向中小企业的语音接待员工作流构建器SaaS产品，让非技术用户在10分钟内通过可视化拖拽搭建可运行的语音接待员，同时支持业务复杂后的高上限扩展。

### 1.2 目标用户

| 用户画像 | 特征 | 核心诉求 |
|---------|------|---------|
| 小企业主(1-20人) | 无技术团队，无IT预算 | "10分钟搭一个能用的语音接待员" |
| 中型企业团队管理者(20-200人) | 有客服团队，需要分流和自动化 | "业务复杂了能不能扛住" |
| SaaS/在线业务运营者 | 无电话号码需求，需网站嵌入通话 | "客户在网站上直接跟我语音沟通" |

### 1.3 核心价值主张

**"10分钟可搭建、高上限可扩展"**——从拖拽搭建到AI增强到运营洞察，全链路覆盖语音接待员的创建、测试、发布、运营、迭代。

### 1.4 成功指标

| 指标类型 | 指标 | 目标值 |
|---------|------|--------|
| **北极星指标** | 周活跃发布工作流数 | MVP: 500; V1.0: 2000; V2.0: 8000 |
| 关键结果1 | 注册→首次发布时间 | < 15分钟 |
| 关键结果2 | 首周留存率 | > 40% |
| 关键结果3 | 付费转化率 | > 8% (V1.0) |
| 关键结果4 | AI意图识别准确率 | > 90% (V1.0) |
| 关键结果5 | 客户NPS | > 30 (MVP); > 50 (V2.0) |

## 2. 功能需求清单

### 2.1 流程编排模块

#### FR-FL-001 画布拖拽创建流程

| 属性 | 内容 |
|------|------|
| **用户故事** | As a 非技术用户, I want to 通过拖拽节点和连线在画布上搭建语音接待员流程, So that 我不需要写代码就能创建可运行的流程 |
| **验收标准1** | Given 用户在画布页面, When 用户从左侧节点库拖拽"问候/开场白"节点到画布, Then 画布上出现该节点并显示默认配置 |
| **验收标准2** | Given 画布上已有节点A和节点B, When 用户从节点A的输出端口拖线到节点B的输入端口, Then 两个节点之间出现带箭头的连线 |
| **优先级** | P0 |
| **关联节点** | 所有节点类型 |

#### FR-FL-002 实时校验

| 属性 | 内容 |
|------|------|
| **用户故事** | As a 流程设计者, I want to 在编辑时实时检测环路、断路和必填项缺失, So that 我不会发布一个有缺陷的流程 |
| **验收标准1** | Given 用户正在连线, When 连线操作会形成环路, Then 系统阻断连线并显示红色错误提示"检测到环路，无法连接" |
| **验收标准2** | Given 用户点击"保存", When 存在未连接的节点（断路）, Then 系统阻断保存并列出所有断路节点 |
| **优先级** | P0 |
| **关联节点** | 所有节点类型 |

#### FR-FL-003 节点参数配置

| 属性 | 内容 |
|------|------|
| **用户故事** | As a 流程设计者, I want to 点击节点后弹出参数配置面板, So that 我可以设置每个节点的具体行为（话术、条件、目标等） |
| **验收标准1** | Given 用户双击画布上的"提问"节点, When 参数面板打开, Then 面板显示所有可配置项（问题文本、输入方式、最大等待时间、重试次数、超时话术），且必填项用黄色标记 |
| **验收标准2** | Given 用户修改了节点配置中的话术文本, When 用户点击"预览", Then 系统在预览面板中播放TTS效果 |
| **优先级** | P0 |
| **关联节点** | 所有节点类型 |

#### FR-FL-004 行业模板

| 属性 | 内容 |
|------|------|
| **用户故事** | As a 新用户, I want to 选择行业模板一键生成完整流程, So that 我不需要从零开始搭建 |
| **验收标准1** | Given 用户点击"创建接待员", When 用户选择"诊所"模板, Then 系统生成包含来电触发器→营业时间判断→意图检测→预约/咨询分支→结束的完整流程 |
| **验收标准2** | Given 用户基于模板创建的流程, When 用户修改任意节点配置, Then 修改即时生效且不影响其他节点 |
| **优先级** | P0 |
| **关联节点** | 来电触发器、问候/开场白、营业时间判断、提问、条件分支、转接呼叫、通话结束 |

### 2.2 AI能力模块

#### FR-AI-001 AI意图检测节点

| 属性 | 内容 |
|------|------|
| **用户故事** | As a 流程设计者, I want to 使用AI意图检测节点让来电者用自然语言说出需求而非按键选择, So that 减少通话步数和放弃率 |
| **验收标准1** | Given 用户添加了AI意图检测节点并配置了意图列表[咨询,预约,投诉], When 来电者说"我想预约下周三的咨询", Then 系统识别意图为"预约"且置信度>0.7，并路由到预约分支 |
| **验收标准2** | Given AI意图检测节点的置信度阈值为0.7, When 来电者的输入与所有意图的匹配度均<0.7, Then 系统走降级路径（按键菜单或转人工） |
| **优先级** | P1 |
| **关联节点** | AI意图检测 |

#### FR-AI-002 知识库问答节点

| 属性 | 内容 |
|------|------|
| **用户故事** | As a 流程设计者, I want to 上传企业文档创建知识库并在流程中使用知识库问答节点, So that 来电者的常见问题可自动回答而不需人工介入 |
| **验收标准1** | Given 用户已上传FAQ文档并创建知识库, When 来电者问"你们的营业时间是什么", Then 系统基于知识库生成回答"我们的营业时间是周一至周五9:00-18:00"并标注引用来源 |
| **验收标准2** | Given 知识库问答节点无法找到相关答案, When 置信度低于阈值, Then 系统按配置走"告知无法回答+转人工"或"尝试回答+标注不确定"路径 |
| **优先级** | P1 |
| **关联节点** | 知识库问答 |

#### FR-AI-003 通话摘要生成

| 属性 | 内容 |
|------|------|
| **用户故事** | As a 团队管理者, I want to 每通电话结束后自动生成通话摘要, So that 我不需要手动记录通话内容且坐席能快速了解前序对话 |
| **验收标准1** | Given 通话结束节点启用了"生成通话摘要", When 一通电话结束, Then 系统在30秒内生成包含来电意图、关键信息、待办事项的摘要 |
| **验收标准2** | Given 通话摘要已生成, When 用户在运营看板查看该通话记录, Then 摘要显示在通话详情中且可读性评分>4.0/5.0 |
| **优先级** | P1 |
| **关联节点** | 通话结束 |

| **验收标准2** | Given Webhook调用超时(10秒), When 超时发生, Then 系统按配置重试1次，仍超时走失败分支 |
| **优先级** | P1 |
| **关联节点** | Webhook |

## 3. 业务规则库

### 3.1 流程校验规则

| 规则ID | 规则名称 | 触发条件 | 规则逻辑 | 错误提示 |
|--------|---------|---------|---------|---------|
| VAL-001 | 环路检测 | 连线操作时 | 新连线不能使DAG形成环 | "检测到环路，无法连接" |
| VAL-002 | 断路检测 | 保存/发布时 | 除通话结束节点外，所有节点必须有至少1条入连线和1条出连线 | "节点[名称]未连接" |

| VAL-005 | 死路检测 | 保存时(警告) | 非结束节点无出连线 | "节点[名称]无出口路径（建议添加连线）" |

|--------|---------|---------|

### 3.5 运营看板数据计算规则

| 规则ID | 指标名称 | 计算公式 | 说明 |
|--------|---------|---------|------|
| MET-001 | 接通率 | 接通数 / (正常来电 + 振铃未接 + 队列放弃) × 100% | 分母包含放弃的来电 |
| MET-002 | 转化漏斗 | 各关键节点的到达数递减 | 关键节点由用户标记或系统自动识别 |
| MET-003 | 节点通过率 | 该节点成功执行数 / 到达该节点数 × 100% | "成功执行"= 节点完成且用户进入下一节点 |
| MET-004 | 异常通话占比 | 异常通话数 / 总通话数 × 100% | 异常定义：超时(>10min)/路由失败/ASR连续3次未识别/用户主动挂断 |
| MET-005 | 平均通话时长 | 总通话时长 / 接通数 | 仅计算接通的通话 |
| MET-006 | 客户满意度 | 所有评分通话的评分总和 / 评分通话数 | 评分范围1-5，仅计算完成评分的通话 |

## 4. 非功能需求

### 4.1 性能

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 流程加载时间 | < 2秒 | 打开已有流程画布的时间 |
| 画布拖拽延迟 | < 50ms | 节点拖拽的视觉响应延迟 |
| 节点配置面板打开 | < 300ms | 双击节点到参数面板完全渲染 |
| 通话接听延迟 | < 2秒 | 来电到问候语开始播放 |
| ASR识别延迟 | < 500ms | 用户说完话到识别结果返回 |
| AI意图检测延迟 | < 800ms | 含LLM推理的端到端延迟 |
| 并发通话支持 | MVP: 50并发; V1.0: 500并发; V2.0: 5000并发 | 单租户同时进行的通话数 |

### 4.2 安全

| 需求 | 说明 |
|------|------|
| 通信加密 | 所有通话媒体流SRTP加密；信令TLS加密；API HTTPS only |
| 数据隔离 | 多租户数据隔离（共享数据库+tenant_id行级隔离）；每个租户的流程数据、通话记录、录音互不可见 |
| 权限控制 | RBAC模型：Owner/Admin/Editor/Viewer四级权限；API Token权限范围限定 |
| 通话录音安全 | 录音存储加密(AES-256)；访问审计日志；按合规要求设置保留期后自动删除 |

### 4.3 可用性

| 需求 | 说明 |
|------|------|
| SLA目标 | MVP: 99.5%; V1.0: 99.9%; V2.0: 99.95% |
| 容灾策略 | 多可用区部署；数据库主从复制+自动故障切换；通信接入双供应商(Twilio+Telnyx) |
| 降级方案 | 通信供应商故障→自动切换备用供应商；AI服务故障→降级到规则流程（按键菜单）；平台故障→来电走降级流程（播放维护提示+转备用号码） |

### 4.4 合规

| 需求 | 说明 |
|------|------|
| 通话录音法规 | 遵循当地录音通知法规（如美国需通知"此通话可能被录音"）；录音节点在问候语后自动插入通知话术 |
| 数据留存 | 通话记录保留90天（默认）；录音保留30天（默认）；可配置延长至1年 |
| GDPR | 用户数据可导出/删除；通话记录包含PII需加密存储；用户可请求删除个人数据 |

## 5. 开放问题清单

### OP-001 AI模型选择策略

| 维度 | 内容 |
|------|------|
| **是什么** | AI节点使用哪个LLM：自研微调模型 vs 通用大模型(GPT-4o-mini/Claude) |
| **为什么还没决定** | 自研模型成本可控但前期投入大；通用模型效果好但每分钟成本$0.02-0.05且存在供应商锁定风险 |
| **备选方案A** | 全部使用GPT-4o-mini（延迟低、效果好、成本$0.003/1K tokens） |
| **备选方案B** | 意图检测用微调BERT模型（成本$0.0005/次、延迟100ms），知识库问答用GPT-4o-mini |
| **利弊** | A: 上线快但成本随规模线性增长；B: 前期投入2-4周但意图检测成本降低83% |
| **建议方向** | V1.0先用方案A快速验证，同时收集意图数据；V1.5用方案B微调意图检测模型降本 |

### OP-002 计费模型

| 维度 | 内容 |
|------|------|
| **是什么** | 按通话分钟计费 vs 按月套餐计费 vs 混合计费 |
| **为什么还没决定** | 纯按量计费对低用量用户门槛低但收入不稳定；纯套餐计费收入稳定但低用量用户觉得贵 |
| **备选方案A** | 纯按量：$0.10/min + AI按量 |
| **备选方案B** | 阶梯套餐：Starter $49/月(200min) + 超出$0.08/min |
| **备选方案C** | 混合：基础套餐$29/月(含100min+1号码) + 超出按量 + AI按量 |
| **建议方向** | 方案C，兼顾低门槛和收入稳定性 |

### OP-003 多语言支持策略

| 维度 | 内容 |
|------|------|
| **是什么** | 产品界面和通话语音的多语言支持优先级 |
| **为什么还没决定** | 中文市场先发但英文市场规模更大；ASR/TTS多语言质量参差不齐 |
| **备选方案A** | MVP仅中文+英文，V1.0扩展日韩 |
| **备选方案B** | MVP中文+英文+日文，利用ElevenLabs多语言TTS |
| **建议方向** | 方案A——MVP聚焦中文+英文，ASR用Deepgram（多语言）、TTS用ElevenLabs（多语言），但产品界面只翻译中英文 |

### OP-004 号码供应商冗余

| 维度 | 内容 |
|------|------|
| **是什么** | 是否在MVP阶段就接入双供应商（Twilio+Telnyx） |
| **为什么还没决定** | 双供应商提高可用性但增加开发量和运营复杂度 |
| **备选方案A** | MVP仅Twilio，V1.0加Telnyx |
| **备选方案B** | MVP同时接入Twilio+Telnyx |
| **建议方向** | 方案A——MVP单供应商降低复杂度，抽象通信接口层为V1.0切供应商做准备 |

### OP-005 实时通话干预

| 维度 | 内容 |
|------|------|
| **是什么** | 管理者是否能在通话进行中介入（如强制转人工、终止通话） |
| **为什么还没决定** | 增加系统复杂度（需要实时控制通道）且有法律风险（单方监听/终止） |
| **备选方案A** | V1.0仅监控不可干预，V2.0加"转人工"干预 |
| **备选方案B** | V1.0即支持"强制转人工"按钮 |
| **建议方向** | 方案A——先做好监控和告警，干预能力延后。紧急场景可通过"暂停接待员"间接处理 |
